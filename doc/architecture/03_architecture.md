## 1. 系统概述

### 1.1 系统定位

运维任务调度系统是一个分布式、可扩展的运维脚本管理和执行平台，支持脚本集中管理、定时调度、多节点执行等功能。

### 1.2 核心特性

- **分布式架构**：管理节点与执行节点分离，支持水平扩展
- **Agent执行模式**：脚本由Agent节点执行，管理节点不直接执行
- **异步任务**：支持异步任务提交和执行
- **高可用性**：管理节点故障不影响已提交任务的执行
- **权限控制**：基于角色的访问控制（RBAC）

### 2.2 架构说明

#### 2.2.1 用户层

- **前端应用**：基于React + TypeScript + Tailwind CSS构建的单页应用
- **访问方式**：通过浏览器访问，与管理节点通过HTTP/HTTPS通信

#### 2.2.2 管理节点

管理节点是系统的核心控制中心，负责：

- **API层**：提供RESTful API接口，处理前端请求
- **业务层**：实现核心业务逻辑
  - 脚本管理
  - 任务调度
  - 执行记录管理
  - 节点管理
  - 用户权限管理
- **数据层**：使用SQLite存储系统数据
- **调度器**：使用APScheduler实现定时任务调度
- **消息队列**（可选）：用于任务分发和结果收集

#### 2.2.3 执行节点（Agent）

执行节点是实际执行脚本的节点，负责：

- 接收管理节点下发的任务
- 执行脚本
- 收集执行日志和结果
- 上报执行状态和心跳信息

## 4. 执行流程

### 4.1 手动执行流程

```
用户 → 前端 → 管理节点API → 任务分发 → Agent执行 → 结果上报 → 执行记录
```

**详细步骤**：

1. 用户在前端选择脚本，配置执行参数（节点、环境等）
2. 前端调用执行API，提交执行请求
3. 管理节点创建执行记录，状态为`pending`
4. 管理节点将任务分发给目标Agent
5. Agent接收任务，更新执行状态为`running`
6. Agent执行脚本，收集日志
7. Agent上报执行结果和日志
8. 管理节点更新执行记录状态（`success`/`failed`）
9. 前端实时显示执行进度和结果

### 4.2 定时执行流程

```
调度器 → 触发任务 → 任务分发 → Agent执行 → 结果上报 → 执行记录
```

**详细步骤**：

1. 调度器根据Cron表达式触发任务
2. 管理节点创建执行记录，状态为`pending`
3. 管理节点将任务分发给目标Agent
4. 后续步骤同手动执行流程

### 4.3 节点心跳流程

```
Agent → 心跳上报 → 管理节点 → 更新节点状态
```

**详细步骤**：

1. Agent定期（如每30秒）向管理节点发送心跳
2. 管理节点更新节点的最后心跳时间
3. 管理节点检查节点超时，标记离线节点
4. 前端实时显示节点状态

## 7. 安全设计

### 7.1 认证与授权

- **认证**：基于JWT Token的用户认证
- **授权**：基于RBAC的权限控制
- **角色**：admin、ops、readonly

### 7.2 数据安全

- **密码加密**：使用bcrypt加密存储用户密码
- **HTTPS**：生产环境强制使用HTTPS
- **敏感数据**：日志中不记录敏感信息

### 7.3 接口安全

- **API限流**：防止恶意请求
- **IP白名单**：限制访问来源
- **操作审计**：记录所有敏感操作

## 13. 架构约束

### 13.1 必须遵守的约束

1. **管理节点不直接执行脚本**：所有脚本执行必须通过Agent完成
2. **Agent执行架构**：采用Agent模式，支持分布式执行
3. **异步任务支持**：任务提交和执行异步进行
4. **水平扩展支持**：系统设计支持动态增减节点

### 13.2 技术约束

1. 前端必须使用React + TypeScript
2. 后端必须使用FastAPI + Python
3. 数据库必须使用SQLite
4. API必须遵循RESTful规范
