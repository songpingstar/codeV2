## 1. 产品概述

### 1.1 产品背景

随着企业IT系统规模的不断扩大，运维任务的数量和复杂度日益增长。传统的手动运维方式存在效率低下、容易出错、难以追踪等问题。运维任务调度系统旨在提供一个集中化、自动化的运维脚本管理和执行平台，帮助企业提高运维效率，降低运维风险。

### 1.2 产品目标

- **集中管理**：统一管理所有运维脚本、执行节点和调度任务
- **自动化调度**：支持定时任务、触发式任务等多种调度方式
- **可追溯性**：完整记录每次脚本执行的详细信息，便于审计和问题排查
- **高可用性**：支持多节点分布式执行，确保任务可靠执行
- **权限控制**：基于角色的访问控制，保障系统安全

### 1.3 目标用户

| 用户角色 | 主要职责 |
|---------|---------|
| 系统管理员 | 系统配置、用户管理、权限分配 |
| 运维工程师 | 脚本开发、任务创建、执行监控 |
| 只读用户 | 查看脚本、任务和执行记录 |

## 2. 功能模块

### 2.1 仪表盘 (Dashboard)

**功能描述**：系统运行状态总览，展示关键指标和最近执行记录

**主要功能**：
- 显示今日执行任务数、成功率、在线节点数等关键指标
- 展示脚本类型分布（Python、Shell）
- 展示调度任务统计（定时任务、触发式、手动）
- 显示最近执行记录列表

**权限说明**：
- 所有角色可查看

**验收标准**：
- [ ] 统计数据实时更新
- [ ] 支持点击执行记录跳转到详情页

---

### 2.2 脚本管理 (Script Management)

**功能描述**：管理 Python 和 Shell 运维脚本的生命周期

**主要功能**：
- **脚本列表**：展示所有脚本，支持按名称、类型、分类筛选
- **新建脚本**：创建新的脚本，填写名称、类型、分类、维护人、描述等信息
- **编辑脚本**：修改脚本的基本信息和内容
- **删除脚本**：删除不再使用的脚本
- **查看详情**：查看脚本的完整信息和代码内容
- **立即执行**：手动触发脚本执行，选择执行节点和环境
- **脚本分类**：支持动态分类管理，系统预设6个分类（监控告警、维护清理、备份恢复、部署发布、故障处理、配置管理），管理员可在系统设置中新增、编辑、删除分类

**权限说明**：
- 系统管理员：所有权限
- 运维工程师：可创建、编辑、执行脚本，不可删除
- 只读用户：仅可查看

**验收标准**：
- [ ] 脚本列表支持分页和筛选
- [ ] 脚本代码支持语法高亮
- [ ] 执行时需选择目标节点和环境
- [ ] 删除脚本需二次确认

---

### 2.3 任务调度 (Task Scheduling)

**功能描述**：管理和调度定时执行的运维任务

**主要功能**：
- **任务列表**：展示所有调度任务，支持按名称、状态筛选
- **新建任务**：创建新的调度任务，配置任务名称、关联脚本、Cron表达式、执行环境、执行模式（指定节点/所有节点）
- **编辑任务**：修改任务的配置信息
- **删除任务**：删除不再需要的任务
- **启用/暂停**：快速切换任务的启用状态
- **下次执行时间**：自动计算并显示下次执行时间
- **上次执行状态**：显示上次执行的结果（成功/失败）

**权限说明**：
- 系统管理员：所有权限
- 运维工程师：可创建、编辑任务，可启用/暂停，不可删除
- 只读用户：仅可查看

**验收标准**：
- [ ] Cron表达式支持可视化编辑
- [ ] 支持选择指定节点或所有节点执行
- [ ] 任务状态切换即时生效
- [ ] 显示任务执行历史

---

### 2.4 执行记录 (Execution History)

**功能描述**：查看和分析脚本执行历史记录

**主要功能**：
- **记录列表**：展示所有执行记录，支持按脚本名称、执行人、状态、环境筛选
- **查看日志**：查看单次执行的详细日志
- **统计信息**：显示总执行次数、成功次数、失败次数、成功率

**权限说明**：
- 所有角色可查看

**验收标准**：
- [ ] 执行记录支持分页
- [ ] 日志详情支持实时滚动
- [ ] 支持日志下载和复制
- [ ] 执行中的任务显示实时进度

---

### 2.5 节点管理 (Node Management)

**功能描述**：管理和监控脚本执行节点

**主要功能**：
- **节点列表**：展示所有节点，支持按名称、IP、环境、状态筛选
- **新增节点**：添加新的执行节点，配置节点名称、IP、环境、标签
- **编辑节点**：修改节点的配置信息
- **删除节点**：移除不再使用的节点
- **节点状态**：显示节点在线/离线状态、最近心跳时间
- **资源监控**：显示节点的CPU、内存、磁盘使用率
- **节点详情**：查看节点的详细信息和执行历史

**权限说明**：
- 系统管理员：所有权限
- 运维工程师：可查看节点详情，不可增删改
- 只读用户：仅可查看

**验收标准**：
- [ ] 节点状态实时更新
- [ ] 支持节点标签管理
- [ ] 离线节点自动标记
- [ ] 资源使用率支持阈值告警

---

### 2.6 系统设置 (System Settings)

**功能描述**：配置系统参数和用户权限

**主要功能**：
- **用户与权限**：
  - 用户管理：创建、编辑、删除用户
  - 角色管理：分配用户角色（系统管理员、运维工程师、只读用户）
  - 权限配置：配置各角色的访问权限
- **脚本分类管理**：
  - 创建、编辑、删除脚本分类
  - 配置分类名称和描述
- **执行环境配置**：
  - 配置默认Shell（Bash、Sh、Zsh、Python3）
  - 配置脚本超时时间
  - 配置最大并发执行数
  - 配置工作目录
  - 配置环境变量
- **通知配置**：
  - 邮件通知：配置SMTP服务器、端口、发件人邮箱
  - Webhook通知：配置Webhook URL
- **安全设置**：
  - 配置登录尝试次数限制
  - 配置锁定时长
  - 配置IP白名单
  - 启用/禁用双因素认证
- **系统参数**：
  - 配置系统名称
  - 配置日志保留天数
  - 配置数据备份时间和频率

**权限说明**：
- 仅系统管理员可访问

**验收标准**：
- [ ] 配置修改后立即生效
- [ ] 敏感操作需二次确认
- [ ] 支持配置导出和导入
- [ ] 提供配置恢复功能

## 3. 非功能需求

### 3.1 性能要求

- 系统响应时间：页面加载时间 < 2秒
- 并发支持：支持至少50个并发用户
- 脚本执行：支持单脚本在多个节点并发执行

### 3.2 可用性要求

- 系统可用性：99.9%
- 支持水平扩展，可动态增减执行节点
- 管理节点故障不影响已提交任务的执行

### 3.3 安全性要求

- 用户密码加密存储
- 支持HTTPS访问
- 敏感操作需二次确认
- 完整的操作日志审计

### 3.4 可维护性要求

- 提供清晰的错误提示和日志
- 支持系统健康检查
- 提供数据备份和恢复功能

---

## 4. 系统约束

### 4.1 架构约束

- 管理节点不直接执行脚本
- 采用Agent执行架构，脚本由Agent节点执行
- 支持异步任务执行
- 支持水平扩展

### 4.2 技术约束

- 前端：React + TypeScript + Tailwind CSS
- 后端：FastAPI + Python
- 数据库：SQLite
- 通信协议：HTTP/REST API

## 6. 用户故事

### 6.1 作为运维工程师，我想要...

- 创建和管理运维脚本，以便统一管理所有脚本
- 设置定时任务自动执行脚本，以便减少手动操作
- 查看脚本执行历史和日志，以便排查问题
- 监控节点状态和资源使用，以便及时发现异常

### 6.2 作为系统管理员，我想要...

- 管理用户和权限，以便控制访问范围
- 配置系统参数，以便适配不同环境
- 查看系统运行状态，以便了解整体情况

### 6.3 作为只读用户，我想要...

- 查看任务调度情况，以便了解任务安排
- 查看执行记录和日志，以便了解执行结果
